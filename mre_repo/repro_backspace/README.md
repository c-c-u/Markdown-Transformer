# 回格 bug 的最小可复现实例

## 样例

画布里先插入一个**求和结构**，再在它的**右侧空位**键入 `x+1`。模型上就是：

```
[空位]  [求和结构]  [文本 x+1]
   0         1          2
```

## 复现步骤（最少操作）

1. 插入「∑ 求和」结构；
2. 把光标放到**最左侧的空位**（公式开头那个看不见的输入位置，下标 0）；
3. 按一次**回格**。

## 现象

旧实现里，回格会把光标**右侧**的求和结构整体删掉 —— 删除方向应该是左侧，
右侧的内容不应该被碰到。这就是「在结构最左侧按回格会删除右侧的内容」。

（编辑状态下按「→ 到行尾再回格」的对照情形：光标在 `x+1` 开头时按回格，
整体删除的是**左侧**求和，这是正确的。）

## 根因（最小代码）

回格/Delete 找「删除方向上的结构」时，旧实现从行尾往行首扫描，
只跳过光标所在的那个元素，没有限制扫描方向：

```python
i = len(root.items) - 1          # 从行尾开始
while 0 <= i < len(root.items):
    if i == index:               # 只跳过光标元素
        i -= 1
        continue
    if is_structure_item(root.items[i]):
        return root, i           # ← 光标左侧为空时，会返回右侧的结构
    i -= 1
```

正确做法：回格只从 `index - 1` 往 0 扫，Delete 只从 `index + 1` 往后扫，
遇到可编辑文本就停止（文本挡在中间时不能跨过去删更远的结构）。

## 修复

- `formula_editor_app/model.py` 的 `_structure_target()`：改为**只在同槽位、沿删除方向**扫描并遇到文本即停；
  `delete_structure_toward()` 不再向上层槽位查找、也不再回头看另一侧。
- `formula_editor_app/app.py` 的 `_remove_at_caret()`：回格落在文本开头且左侧没有相邻结构时**什么都不做**，
  不再回退成“删除右侧字符”。
- `formula_editor_app/smoke.py` 增加对应断言：行首空位按回格不删右侧结构、结构右侧空位按回格整删左侧结构、
  结构内部方框里不整删外层结构。
